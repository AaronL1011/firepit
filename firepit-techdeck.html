The idea

The boundary belongs to the one who bears the risk.

We never made fire safe. We built pits around it.

Four parts, one job each

Sandbox

The declared boundary. Paths, hosts, tools, minutes. Nothing ambient.

Egress proxy

The only way out. Holds the keys.

Audit log

Every crossing, recorded before it happens.

Kill switch

Stops any sandbox through the kernel.

What is the agent?

The agent is everything that acts on the model’s output

Tool sandbox

  • Wraps git, bash, python
  • Harness reads, fetches, renders outside

Firepit sandbox

  • Harness and every process inside
  • Model reached through the egress proxy

The honest part

Firepit makes the sandbox safe. Nothing makes the AI safe.

  • It can’t judge what goes through the proxy.
  • It can’t unsend what already left.
  • It can’t stop the agent misbehaving.

Prompt injection, reward hacking, a buggy harness: the boundary holds whatever the cause.

If the AI must choose to behave, there is no boundary.

How a Linux sandbox holds the boundary

  • Group: one cgroup per sandbox, under a systemd user service
  • Seal: user, mount and network namespaces via bwrap
  • Kill: write 1 to cgroup.kill, no runtime needed
